# Desktop project memberships

Desktop project names and task assignments are stored separately from app-server projects. In both reviewed builds, a rollout gate (`localProjectTaskMembership`, Statsig `1498636858`) controls the existing membership synchronizer. When disabled, projects are imported but assigned tasks can retain a null backend `project_id`. Backend API consumers then lack the desktop assignment. Working-directory basenames cannot recover that assignment, especially when multiple projects share a directory.

This optional app-copy module enables only the existing native synchronizer. It uses recorded desktop assignments and the existing mapping from desktop project IDs to app-server project IDs. Native backend support/readiness checks remain intact. New local tasks receive a project ID at creation; later project moves and clearing assignments call `thread/metadata/update`. The native historical migration processes active tasks; archived or absent tasks remain in its pending list and are handled by the existing unarchive/create paths. No project is inferred from `cwd`, and the relay does not rewrite project names.

The module defaults to `disabled`, including configurations saved before it existed. Inspect `repair-projects` before opting in, then set `"project-memberships": "enabled"` (or consciously choose `auto`) in your patch configuration and rebuild. **The native initial migration follows desktop assignments and can overwrite a different backend membership.** The explicit repair tool reports conflicts and refuses to replace them; enabling this synchronizer uses the application's own migration behavior instead. Back up existing data and resolve conflicting assignments before opting in.

Disabling the module stops future synchronization through this path when the upstream gate is off. It does not undo already persisted memberships; an upstream-enabled gate continues its normal native behavior. Removing the app copy also preserves your Codex project/task data.

Source-bound tests execute the actual synchronizer with disposable in-memory state: gate disabled, initial migration, two named projects sharing a directory, new assignments, moves, clearing, deferred archived/absent tasks, backend-readiness checks and remote-host guards. All app-module selections also verify independent source/output hashes and composition with `browser-service-path`, which edits the same main bundle. Phone display/reconnect and desktop interactions remain separate live acceptance checks.

**Known limitation:** in the September 30 Windows/WSL acceptance check, the ChatGPT Android app still displayed folder names after the backend memberships were synchronized correctly. This module makes the assignments available to backend APIs; it does not establish that Remote Control displays desktop project names. That display issue remains unresolved.
